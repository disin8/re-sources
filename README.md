# re • sources

A hand-checked directory of design tools and resources for developers — fonts,
color palettes, icons, AI tools, mockups, animation libraries, localization,
deployment and testing.

Every entry records its **license**, **pricing model**, **platform** and the
**date it was last reviewed**, so a resource can be shipped without a legal
round-trip.

---

## Stack

- [Next.js 15](https://nextjs.org) (App Router, static generation)
- [Tailwind CSS](https://tailwindcss.com) + shadcn/ui primitives
- [Vercel Analytics](https://vercel.com/docs/analytics) + Speed Insights
- Content is plain TypeScript — no CMS, no database

## Getting started

```bash
pnpm install
pnpm dev
```

### Scripts

| Command | What it does |
| --- | --- |
| `pnpm dev` | Start the dev server |
| `pnpm build` | Production build |
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm lint` | ESLint |
| `pnpm check:catalog` | Catalog integrity check — duplicate slugs, missing fields, broken asset paths, dead collection references |
| `pnpm check:links` | Integrity check **plus** an external link check on every outbound URL |
| `pnpm verify` | `typecheck` + `lint` + `check:catalog` |

## Content model

Every resource lives in `content/<category>.ts` and follows the `IContent`
interface in `types/content.ts`:

```ts
const entry: IContent = {
  slug: 'fontshare', // URL-safe, unique across the catalog
  name: 'Fontshare',
  description: 'Free, production-ready fonts from Indian Type Foundry.',
  details: 'Two to three sentences with real specifics…',
  url: 'https://www.fontshare.com/',
  image: '/images/fonts/fontshare.webp', // screenshot, required for every entry
  type: 'font-library',
  price: 'free', // free | freemium | paid | subscription
  license: 'commercial', // open-source | commercial | personal | proprietary | free
  licenseLabel: 'Free for commercial use',
  platforms: ['web'],
  tags: ['variable', 'web fonts'],
  addedAt: '2024-08-12',
  reviewedAt: '2026-10-06',
  featured: true,
  isNew: true,
}
```

Categories are registered once in `config/categories.ts` (slug, title, meta
description, intro copy, keywords, FAQ). The slug is the URL segment, so
changing it means adding a redirect.

`content/collections.ts` holds editorial shortlists. A collection references
resources by slug and renders at `/collections/<slug>`.

### Adding a resource

1. Add the entry to the matching `content/<category>.ts`.
2. Drop a screenshot at `public/images/<category>/<slug>.webp` — every published
   entry needs one.
3. Run `pnpm check:catalog` — it rejects duplicate slugs, missing fields,
   missing assets, malformed dates and dangling collection references.
4. Run `pnpm check:links` to confirm the URL resolves.

### Adding a category

1. Add the entry to `config/categories.ts`.
2. Add a `content/<category>.ts` file and register it in `content/index.ts`.
3. Add it to `config/sidebar.ts` so it appears in the navigation.
4. If the slug replaces an old one, add a 301 in `next.config.mjs`.

## SEO

### URL structure

| Route | Purpose |
| --- | --- |
| `/` | Homepage — category index, collections, editor picks |
| `/<category>` | Category landing page — the main organic entry point |
| `/collections` | Editorial collection index |
| `/collections/<slug>` | Long-tail landing page for a specific job |
| `/resources/<slug>` | Resource detail page — license, price, dates, related tools |
| `/about` | Editorial policy, criteria, author |
| `/submit` | Suggest a resource |
| `/feed.xml` | RSS feed of the catalog |
| `/api/resources` | JSON API, filterable by `category`, `price`, `type`, `tag`, `q` |
| `/robots.txt`, `/sitemap.xml` | Generated by `app/robots.ts` and `app/sitemap.ts` |

### What is implemented

- **Per-route metadata** — unique title, description, keywords, canonical URL,
  Open Graph and Twitter card. One `<h1>` per page.
- **Structured data** — `WebSite` + `SearchAction` sitewide, `ItemList` and
  `BreadcrumbList` on listings, `FAQPage` on category pages, `WebPage` +
  `SoftwareApplication` on resource pages, `CollectionPage` on the homepage.
- **`robots.txt`** — points at the sitemap, blocks `/api/`.
- **`sitemap.xml`** — every category, collection and resource URL, with
  `lastModified` taken from each resource's `reviewedAt`.
- **Social images** — 1200×630 PNGs generated per route by `next/og`:
  the site default, one per category, one per resource.
- **301 redirects** — legacy category slugs (`/typography`, `/colors`, …) and
  legacy resource paths (`/<category>/<slug>`) redirect to the new structure.
- **Canonical host** — `middleware.ts` 301-redirects any non-canonical host to
  the canonical origin and serves `X-Robots-Tag: noindex` off production.
- **Preview noindex** — preview deployments return an empty sitemap and are
  excluded from indexing.

### Required production configuration

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | The canonical origin, e.g. `https://your-domain.com`. Every canonical, sitemap and OG URL derives from it. **Set this before the domain goes live.** |

### Custom domain cutover

1. Point the domain at the project in Vercel (**Settings → Domains**).
2. Set `NEXT_PUBLIC_SITE_URL` to the new origin and redeploy.
3. `middleware.ts` then 301-redirects the old `*.vercel.app` host to the new
   domain. Confirm the old host still resolves first — Vercel must keep
   serving it for the redirect to fire.

### Search engines

Verification files are committed at `public/google354ef6537d2d6965.html` and
`public/yandex_c81920c4302c67cd.html`.

- **Google Search Console** — add the domain, verify with the HTML file, then
  submit `https://your-domain.com/sitemap.xml`.
- **Bing Webmaster Tools** — import from Search Console and verify with the
  Yandex file (accepted by Bing).

### Avoiding doorway pages

Filter combinations (`?price=free&type=saas`) are rendered from the same
canonical category URL and always canonicalise back to it. Only the base
category, collection and resource URLs are submitted in the sitemap — filtered
variants are never listed.

## Editorial process

| Role | Responsibility |
| --- | --- |
| Editor | Adds entries, writes the description, sets license and pricing |
| Reviewer | Re-checks the URL, license and pricing on the weekly cadence |

Rules the catalog enforces:

- Only state a license when the vendor publishes it. Otherwise use
  `proprietary` with a factual label.
- A free tier is only called free if it is usable. `freemium` means a real
  free tier with a paid upgrade.
- `reviewedAt` is bumped every time the entry is manually checked. The weekly
  link check in CI confirms the URL still resolves.
- No entry ships without a screenshot in `public/images/<category>/`. Entries
  without one are parked in `content/without-screenshots.ts` and stay out of
  the published catalog.
